# Active live execution boundary for an AI-led planner

Inspected commit `30eab9e`; 10 September 2026. Scope is the current `modulePlannerMode=apply` Speak and Type path. This is an architecture inventory, not an implementation or deployment. The Option 2 adversarial scripts remain separate evidence. No production file was changed and no provider requests were made for this inventory.

## The boundary to preserve

The simplest compatible design is: AI proposes the meaning of the current conversation; an independent AI verifier approves that exact proposal and exact confirmation; deterministic code binds the approved artefacts to their source turns and executes only the certified native inputs after informed approval. If the first proposal fails for repairable reasons, permit one further AI proposal and one independent audit, within the same operation. A second reasoning attempt must not inherit permission from the first.

Approval itself has two different parts. Whether a person’s words mean approval, a correction, a condition, uncertainty or a question is a semantic decision. Whether the answer belongs to the right delivered offer, whether the offer is current, and whether it already ran are protocol decisions. Keep those parts separate. There is no need for deterministic financial-language parsing in the execution barrier.
