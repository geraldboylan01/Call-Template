# Story screen: differences from the B1.5 brief

Compared on 27 October 2026 with sections 1 (including “Every placeholder carries its source”) and 3 of [the B1.5 brief](plan-pack-b15-story-brief.md), after merging `origin/main` into `plan-pack-story-view`. This is the screen and its data model, not an implementation of the B1.5 compiler/checker. Neither module screens nor `docs/prompt-pack/` are changed.

## Section 1: placeholders and sources

| Requirement | Original screen | Result in this PR / remaining work |
|---|---|---|
| The compiler computes the registry from the priced route. | Hand-authored sample display text and source hints; a demo session built separately through the module pipeline. | **Connected in `story/compiled-plan`** (`js/plan_story_compiled.js`, see [plan-story-view.md](plan-story-view.md)); formerly: still to connect. Build `planStory` from a compiled plan's inputs, results and versions. Neither sample modules nor a separately authored example payload proves a production story. |
| Story data sits beside `narration` as optional `story[routeId]` in the plan. | The session owns `planStory.stories`, registries, route summaries and chapter-to-module IDs. | **Adapter pending.** The session format is a screen projection, not the plan-pack format. Keep B0/B1 `narration`; no compiler changes in this PR. |
| Every placeholder has its source, including unlinked facts and plan-owned facts. | Only some sample facts carried sources; plain facts bypassed source validation. | **Fixed in the screen model.** Every referenced fact now needs a source naming exactly one module chapter or plan panel; source IDs are validated. Sample plan-owned facts point at panels. Actual production source generation is pending. |
| `caseId` comes from the route's `chapterCases`; `nativeCaseId` selects the case inside that module. | Both fields were carried, but navigation, off-route detection and restoration used `caseId` alone. | **Native navigation fixed.** Selection and restoration now use `nativeCaseId` when supplied, and verify the selected case. **Compiled mapping pending:** the screen still trusts registered chapter/case metadata; it does not derive or prove it against `chapterCases`. | `{@current.<key>}` uses the current-position compiled case. | A prefix had no special compiled-plan treatment. | **Source identity preserved and tested.** The model does not replace a current fact's registered source with the selected alternative. | `focusTargetId` identifies the presenter's exact target where available. | Carried but ignored; outlining used text or a CSS selector. | **Partly fixed.** Existing catalogue IDs are checked for the destination module, availability and native scenario, then resolved for holdings, rows, metrics, report items/disclosures, timeline events, blocks and whole charts. | A plan-owned fact opens its own panel. | Panel metadata was supported by the pure handoff, but the app only displayed an unavailable message and reported success. | **Failure reporting fixed.** The app reports an unavailable panel as unavailable. **Panel navigation remains to build** with the plan view. | Only `{@key}` marks a link; code constructs its destination. | Already enforced, including refusal of stray braces and extra markers. | **Unchanged.** Narration supplies no module, route, URL or target. It also does not read `{figure.<id>}` from `read_figures`. Raw values, units and versioned provenance need a compiled source. |

## Section 3: structure and completeness

| Requirement | Original screen | Result in this PR / remaining work |
|---|---|---|
| Nine prescribed sections, once each, in order. | Eight sample sections; `ledger` missing. Any nonempty, nonduplicate set was accepted. | **Fixed.** The model requires `current_position`, `ledger`, `protecting`, `inefficiencies`, `goals`, `cash_flow_after`, `net_worth_after`, `risks`, `check_next` in exactly that order. A sample ledger paragraph was added. |
| Each section and each goal subsection has `does`, `why`, `gives`, `costs`, `check`. | A partial parts object silently skipped absent parts, or paragraphs bypassed parts entirely. | **Parts validation fixed.** A declared parts object needs all five nonempty parts, and cannot also declare paragraphs. **Larger authoring/schema work deferred:** the sample still uses the screen's paragraph preview format; no per-goal subsection structure is implemented. A resolved preview is not a passed B1.5 completeness check. |
| Every goal is a subsection in the ledger's order. | College, mortgage and retirement share one sample paragraph. | **Pending.** Build ordered goal subsections from compiled goals, including loan goals and dated costs; no ordering is inferred from prose. |
| Current position covers surplus/deficit, spare cash, net worth, solvency or its reason, and pressure points. | Sample surplus, savings and reserve only. | **Pending.** Require the complete compiled fact set or its registered reasons, not merely a section with that ID. |
| Ledger covers available/required resources, one funding method per goal, crossed-off resources and surplus after every step. | No ledger section. | **Structure fixed; content floor pending.** The added preview paragraph is not a compiled resource-ledger explanation or coverage proof. |
| Protecting begins with the reserve, then income gaps and savings duration; the household floor includes `incomeStops` for every earner and `death` for couples/dependants. | Two sample inability-to-work cases; reserve appeared only in current position. | **Reserve placement fixed.** Earner/dependant coverage, a death what-if, stated cover/payout facts and required-what-if checks still need the compiled household and what-if results. |
| Every code-found inefficiency, goal and in-ledger-years freed-cash event appears. | A car-loan example and selected goals/events, without computed coverage metadata. | **Pending.** Compare story references with the compiler's issue list, goals and B1.1 events. Rendering text cannot prove completeness. |
| Cash flow after includes remaining yearly money, freed-cash events and each person's retirement cutoff. | A sample leftover amount only; one freed event appears earlier in prose. | **Pending.** Place and verify the complete compiled events/cutoffs in this section. |
| Net worth after includes its change from current and applicable later-life results. | One sample net-worth figure and the cash/debt movement. | **Pending.** Supply compiled differences and applicable asset/run-out results. B1.6 growth, gift and later-life stories remain the brief's later extension. |
| Each alternative has a risk tied to its main change, and each chosen what-if cites its household fact. | Two sample rate/cost shocks, without machine-checkable relevance or main-change coverage. | **Pending.** Supply structured what-if evidence, relevance and per-route risk coverage. The current route needs no invented change risk. |
| Missing facts/results/required what-ifs produce code limitations in their section and `check_next`; review items are required. | Free-text check-next items and a preview “Updating” state. | **Pending.** Bind limitations/review items to confirmed facts and follow-up outcomes. Updating is a display state, not a completed calculation or a limitation record. |
| Protection figures are limited to income gap, savings duration and stated money received; forbid cover-needed/gap-against-cover/premiums/products/providers. | Reuses the module's wording/provider bans; no fact-type allowlist. | **Pending.** Add semantic placeholder/source restrictions in the production checker; lexical bans alone cannot prove the allowed protection scope. |
| Refuse rankings, another alternative's facts, and growth variants without disclosure. | Wording/ranking-field bans and registered placeholders; no compiled cross-route or disclosure check. | **Partly fixed.** A stored story's `routeId` must match its route. Cross-alternative references and growth disclosures still need compiled validation. Existing ranking-word regexes remain context-blind and can overreject harmless uses; they are not a complete authoring checker. |
| Neutral current-first order, then cash committed; current plus up to three alternatives. | Displays supplied order and rejects rank fields; normaliser permitted six routes. | **Route cap fixed to four.** The screen preserves input order. The compiler must establish current-first/cash-committed ordering; display strings are not a numeric sorting authority. |
| Invalid production stories are refused with diagnostics. | Invalid session stories are left out with warnings so existing sessions still open. | **Screen behavior retained.** Parser errors carry paths, but session resilience is not production acceptance. B1.5 must refuse an invalid story before release. |

## What the checks establish

`check:plan-story` covers placeholder syntax, typed figures/headings, registered sources, explicit reasons, nine-section order, complete declared parts, stored route identity, native-case selection/restoration and link failure paths.

`check:plan-story-browser` runs the real app and eight sample modules at desktop and phone widths. It follows all fifteen sample links, checks the selected native case and highlighted text, follows existing presenter metric targets even with stale fallback hints, refuses a missing target, and checks returning to the paragraph, off-route restoration, Story/Modules switching and reload.

These are screen and sample regressions. **The two release connections remain a compiled plan as the story's source, and the B1.5 checker proving each linked value/unit/format against the module figure for that compiled route's case.**
